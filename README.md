# Tim Rent Car 3.0

สถานะก่อนส่ง: ดู SUBMISSION-STATUS.md ก่อนกล่าวอ้างว่าผ่านทุกข้อ ยังไม่มีผลผู้ใช้ใหม่จริงและผล uptime ครบเดือน กำหนดส่งคือ 15 พฤศจิกายน 2026

ระบบบริหารจัดการเช่ารถสำหรับส่งและสาธิตโครงการตามขอบเขตที่ตกลง ใช้งานครบ 4 บทบาท โดยการชำระเงินและอีเมลทำงานในสภาพแวดล้อมทดสอบภายในเครื่อง ไม่มีการเรียกเก็บเงินจริงหรือส่งอีเมลออกภายนอก

## เริ่มใช้งาน

หากดาวน์โหลดจาก GitHub ให้เลือก Code → Download ZIP แล้วแตกไฟล์ หรือใช้ git clone จากหน้า repository จากนั้นรัน `npm.cmd ci` ในโฟลเดอร์โปรเจกต์ก่อนเริ่มระบบ GitHub เก็บซอร์สโค้ดและหลักฐานทดสอบ ไม่รวม node_modules ฐานข้อมูลที่ใช้งาน และกุญแจ HTTPS ซึ่งระบบจะสร้างภายในเครื่อง

1. ใช้ Node.js 24 ขึ้นไป (ทดสอบด้วย v24.22.0)
2. แตก ZIP ทั้งโฟลเดอร์ก่อนใช้งาน
3. ดับเบิลคลิก Start-Tim-Rent-Car.cmd
4. เปิด http://127.0.0.1:3003 กดเข้าสู่ระบบ เลือกบัญชีทดสอบ แล้วกดเข้าสู่ระบบอีกครั้ง

ชุด Ready รวม node_modules ภาพ และฟอนต์ เปิดแบบออฟไลน์ได้ ชุดซอร์สโค้ดต้องรัน npm ci ก่อน npm start ตัวเปิดบน Windows จะติดตั้งแพ็กเกจให้หากไม่พบ

```powershell
npm.cmd ci
npm.cmd start
```

หยุดเซิร์ฟเวอร์ที่เปิดจากเทอร์มินัลด้วย Ctrl+C ข้อมูลยังคงอยู่เมื่อเปิดใหม่ เปลี่ยนพอร์ตได้ด้วย $env:PORT='3002' ก่อนรัน เวอร์ชัน 3 ใช้พอร์ต 3003 แยกจากเวอร์ชันเดิมที่อาจเปิดอยู่บน 3000

## บัญชีทดสอบ

เปิดจากมือถือผ่านอินเทอร์เน็ตได้ด้วย `Start-Internet-Demo.cmd` หลังตั้งค่า Cloudflare และอีเมลที่อนุญาตตาม [INTERNET-DEMO.md](INTERNET-DEMO.md) โดยใช้ฐานข้อมูลสาธิตแยกจากระบบบนเครื่อง และปิดด้วย `Stop-Internet-Demo.cmd`

ทุกบัญชีใช้รหัสผ่าน Demo1234! ข้อมูลเป็นตัวอย่าง

| บทบาท | อีเมล | หน้าที่ |
| --- | --- | --- |
| ลูกค้า | customer@tim.test | ค้นหา จอง ลงนาม อัปโหลดสัญญา ชำระเงินทดสอบ ดูเอกสารและอีเมลของตน |
| เจ้าหน้าที่บริการ | staff@tim.test | จองให้ลูกค้า ใช้ส่วนลด นัดหมาย รับเงินสด/บัตร/QR ทดสอบ ส่งมอบและรับคืน |

## ขั้นตอนสาธิต

อ่าน DEMO-GUIDE.md สำหรับลำดับนำเสนอและข้อมูลตัวอย่าง

ลูกค้าเลือกรถและช่วงเวลา ตรวจราคา ใช้ SEASON15 ลงนามหรืออัปโหลดสัญญา จากนั้นสร้าง QR เปิดหน้าชำระเงินทดสอบและยืนยันผล ระบบสร้างเลขอ้างอิง เปลี่ยนสถานะการจอง และส่งเข้า Test Inbox พร้อมสัญญา ใบยืนยัน และใบเสร็จ PDF ภาษาไทย 3 ฉบับ

QR ถอดรหัสเป็น URL ได้จริง แต่ชี้ไปหน้าทดสอบในเครื่อง ไม่ใช่ QR โอนเงิน สาธิตบนเครื่องเดียวได้โดยกดเปิดหน้าชำระเงินทดสอบ หากสแกนจากโทรศัพท์ URL 127.0.0.1 จะอ้างถึงโทรศัพท์เอง จึงไม่ใช้จากอุปกรณ์อื่นโดยไม่มีการตั้งเครือข่ายเพิ่มเติม

พนักงานเลือกเงินสดหรือบัตรเครดิตทดสอบได้ เงินสดต้องรับยอดให้เพียงพอ บัตรรับเฉพาะเลขท้ายทดสอบ 4 หลัก เช่น 4242 ไม่ต้องใช้ข้อมูลบัตรจริง ทดสอบชำระไม่สำเร็จแล้วลองใหม่ได้ และการยืนยันซ้ำไม่สร้างยอดหรืออีเมลซ้ำ

รายการรอชำระกันรถ 15 นาทีแล้วหมดอายุ การแก้ไขรถ/วันที่คำนวณราคาใหม่ ล้างสัญญา และให้ลงนามใหม่ พนักงานหรือผู้ดูแลยกเลิกรายการยืนยันพร้อมบันทึกคืนเงินทดสอบได้

## เอกสารและอีเมล

ดาวน์โหลดสัญญา ใบยืนยัน และใบเสร็จจากหน้าการจอง สัญญารวมลายเซ็นที่บันทึก หรือระบุว่ามีสัญญาที่อัปโหลดพร้อมลิงก์ต้นฉบับ เอกสารทุกฉบับระบุว่าใช้สาธิต

Test Inbox แสดงผู้รับ เลขจอง เลขชำระ และรายละเอียด ดาวน์โหลด .eml แบบ MIME พร้อม PDF แนบ 3 ฉบับ เปิดด้วยโปรแกรมอีเมลที่รองรับได้โดยไม่เชื่อมบัญชีอีเมลจริง

examples มีเอกสาร 3 ฉบับและอีเมลที่สร้างจากการทดสอบจริง เลขอ้างอิงตัวอย่างไม่จำเป็นต้องอยู่ในฐานข้อมูลใหม่

## ทดสอบ

```powershell
npm.cmd test
npm.cmd run benchmark
npm.cmd run backup
```

ชุดทดสอบใช้เซิร์ฟเวอร์และฐานข้อมูลชั่วคราวแยกจากข้อมูลสาธิต ผลล่าสุดผ่าน 26 กรณี รวม 6 Test Cases ในรายงาน และกรณี QR, PDF, MIME, สิทธิ์, หมดอายุ, รูปตรวจรถ, ซ่อมบำรุง, ลบ/กู้คืนบัญชี, ราคา, คืนเงินทดสอบ และป้องกันคำขอข้ามเว็บไซต์

benchmark ต้องเปิดเซิร์ฟเวอร์ก่อน ทดสอบ 100 คำขอพร้อมกันต่อหนึ่งงาน ได้แก่ รายการรถ คำนวณราคา และรายการจอง ผลอยู่ใน verification/performance.json เป็นผลเฉพาะเครื่อง ไม่ใช่การรับรองความจุโฮสต์หรือ uptime รายเดือน

REQUIREMENTS.md เทียบ Functional Requirements 30 ข้อและ Non-functional Requirements 10 ข้อ โดยแยกหลักฐานในเครื่องออกจากสิ่งที่ต้องวัดในโฮสต์จริง

## สำรองและกู้คืน

SQLite backup ทำเมื่อเริ่มโปรแกรมและตรวจทุกชั่วโมง หากยังไม่มีไฟล์ของวัน UTC นั้นจะสร้างใน data/backups สั่งทันทีด้วย npm run backup ขณะเซิร์ฟเวอร์ปิดไม่มีงานสำรองทำงาน

ก่อนกู้คืนให้หยุดเซิร์ฟเวอร์ ย้าย data เดิมไปเก็บทั้งชุด สร้าง data ใหม่ แล้วคัดลอกไฟล์สำรองมาเป็น data/rental.sqlite จากนั้นเปิดใหม่ ห้ามนำ WAL/SHM เดิมมารวมกับไฟล์ที่กู้คืน

ZIP ไม่รวมฐานข้อมูลระหว่างพัฒนา เปิดครั้งแรกจะสร้างผู้ใช้ 4 บทบาท รถ 4 คัน SEASON15 และรายการ CAR-003 วันที่ 25–27 พฤศจิกายน 2026 ใหม่โดยอัตโนมัติ

## โครงสร้างและการตั้งค่า

| ไฟล์/โฟลเดอร์ | หน้าที่ |
| --- | --- |
| server.mjs | HTTP/HTTPS, authentication, ข้อมูลหลัก, จองและตรวจรถ |
| features.mjs | Test Gateway เอกสาร อีเมล บำรุงรักษา ราคา ลบ/กู้คืน และ audit |
| documents.mjs | PDF ภาษาไทยและอีเมล MIME |
| public | หน้าจอ ภาพ และฟอนต์ในเครื่อง |
| tests | ชุดทดสอบระบบ |
| scripts/benchmark.mjs | ทดสอบคำขอพร้อมกัน |
| verification | ผลทดสอบและผลวัดประสิทธิภาพ |
| data | ฐานข้อมูลและไฟล์สำรอง สร้างเมื่อเริ่มโปรแกรม |

ตัวแปรสภาพแวดล้อม: PORT เปลี่ยนพอร์ต, DATA_DIR เปลี่ยนที่เก็บฐานข้อมูล, PUBLIC_BASE_URL กำหนด URL ใน QR, TLS_CERT_FILE และ TLS_KEY_FILE เปิด HTTPS ด้วย certificate/key ที่เตรียมไว้, COOKIE_SECURE=1 สำหรับ HTTPS proxy เซิร์ฟเวอร์ HTTPS กำหนด TLS ขั้นต่ำ 1.2 และ Secure cookie อัตโนมัติ

ค่าเริ่มต้น HTTP บน 127.0.0.1 ใช้สาธิตในเครื่อง ยังไม่มีโฮสต์ภายนอกหรือผลวัด uptime 99% รายเดือน ขอบเขตส่งงานนี้ไม่ต้องมีบัญชีธนาคารหรือ SMTP

## หลักฐานเพิ่มเติมรุ่น 3

เปิด http://127.0.0.1:3003/usability สำหรับผู้ใช้ใหม่จริง และ /evidence ด้วยบัญชี admin เพื่อดูผล ระบบแยกผลตรวจเครื่องมืออัตโนมัติออกจากผลผู้ใช้จริง

รัน npm run test:load เพื่อทดสอบ 100 บัญชีแยกเซสชันทำงานครบขั้นตอนผ่าน HTTPS และ npm run test:recovery เพื่อทดสอบเริ่มกลับอัตโนมัติ ใช้ฐานข้อมูลชั่วคราวแยกจากข้อมูลสาธิต

ตัวเปิดหลักใช้ supervisor แล้ว ถ้าใช้ npm start โดยตรงจะไม่ได้เปิด health monitor ต้องใช้ npm run start:monitored เพื่อเก็บ availability log

HTTPS ใช้ Start-HTTPS-Test.cmd และเตรียมความเชื่อถือใบรับรองด้วยตนเองตาม HTTPS-LOCAL.md ค่าเริ่มต้น HTTP สำหรับเปิดดูหน้าเว็บไม่ใช่หลักฐานการเข้ารหัส

อ่าน ACCEPTANCE-PLAN.md สำหรับวิธีเก็บผลผู้ใช้ใหม่และข้อเสนอหลักฐานทดแทนเรื่อง uptime ซึ่งยังต้องให้อาจารย์ยอมรับ ไม่ถือว่าได้รับอนุมัติแล้ว
