# Tim Rent Car

ระบบบริหารจัดการเช่ารถ - รายงานสรุปสำหรับ Portfolio

ผู้จัดทำ Portfolio: รัฐพงศ์ คูสกุลธรรม | มหาวิทยาลัยมหิดล คณะ ICT

JavaScript Node.js 24+ SQLite Thai PDF Test Gateway 

### 1. วัตถุประสงค์และขอบเขต

โครงการเว็บสำหรับสาธิตกระบวนการเช่ารถ ตั้งแต่ค้นหารถ ตรวจช่วงเวลาว่าง สร้างการจองและสัญญา ไปจนถึงส่งมอบ รับคืน และตรวจสภาพรถ มีเอกสาร PDF ภาษาไทยและกลไกชำระเงิน/อีเมลสำหรับทดสอบ

### 2. บทบาทที่ผมรับผิดชอบ

- ออกแบบหน้าเว็บและการนำเสนอข้อมูลของระบบ
- ทดสอบการทำงานและตรวจสอบพฤติกรรมของระบบ
- ใช้ AI ช่วยพัฒนาโครงการและหาแนวทางแก้ปัญหา

บทบาทข้างต้นเป็นข้อมูลที่ผู้สมัครยืนยัน รายการความสามารถของระบบด้านล่างอธิบายภาพรวมโครงการ ไม่ถือว่าโค้ดทุกส่วนเป็นผลงานที่พัฒนาคนเดียว

### 3. ผู้ใช้งานและหน้าที่

| บทบาท | ขอบเขตที่ระบบรองรับ |
| --- | --- |

| เจ้าหน้าที่ | ทำรายการแทนลูกค้า ส่วนลด ส่งมอบ/รับคืน และชำระเงินทดสอบ |
| ผู้ดูแลระบบ | จัดการผู้ใช้ รถ ราคา ส่วนลด รายงาน และประวัติการทำรายการ |
| ผู้ตรวจสภาพ | ตรวจรถ แนบรูปความเสียหาย ประเมินค่าใช้จ่ายและงานซ่อม |

## การทดสอบและหลักฐานที่มีอยู่

### 5. ตัวอย่างกรณี TC2-U: ป้องกันการจองทับซ้อน

| หัวข้อ | รายละเอียด |
| --- | --- |
| เงื่อนไขก่อนทดสอบ | ฐานข้อมูลสาธิตมีลูกค้า C001 และรถ CAR-003 ซึ่งถูกจองวันที่ 25-27 พฤศจิกายน 2026 |
| ข้อมูลที่จะทดสอบ | เลือก CAR-003 รับรถ 26 พฤศจิกายน 2026 เวลา 10:00 และคืนรถ 28 พฤศจิกายน 2026 เวลา 10:00 |
| ขั้นตอน | เข้าสู่ระบบเจ้าหน้าที่ เลือกลูกค้าและรถ กำหนดวันเวลา แล้วพยายามยืนยันการจอง |
| ผลที่คาดหวัง | แจ้งเตือนช่วงเวลาทับซ้อน และไม่สร้างรายการจองซ้ำ |
| หลักฐานที่อ้างอิง | DEMO-GUIDE.md อธิบายวิธีสาธิต และ verification/tests.txt บันทึกผล TC2-U เป็นผ่าน |

แยกผลคาดหวังออกจากผลจริง:  ตารางนี้เป็นสรุปการออกแบบกรณีทดสอบ ส่วนผลผ่านอ้างอิงไฟล์ผลทดสอบอัตโนมัติที่บันทึกไว้ ไม่ใช่การกรอก Actual Result จากการทดลองด้วยตนเองรอบใหม่

### 6. สิ่งที่รายงานผลทดสอบรองรับ

- verification/tests.txt บันทึกชุดทดสอบระบบ 26 กรณี ผ่าน 26 และไม่ผ่าน 0
- มีกรณีจองทับซ้อน จองพร้อมกัน วันคืนก่อนวันรับ และการตรวจสภาพไม่ครบ
- มีกรณีสิทธิ์เข้าถึง การหมดอายุของรายการค้างชำระ และการป้องกันยืนยันชำระซ้ำ
- มีการทดสอบ QR เอกสาร PDF ภาษาไทย และอีเมล MIME พร้อมเอกสารแนบ

### 7. ข้อจำกัดในการอ้างผล

- การชำระเงินและอีเมลเป็น Test Gateway / Test Inbox ไม่มีการรับเงินจริงหรือส่งอีเมลภายนอก
- SUBMISSION-STATUS.md ระบุว่ายังไม่มีผลผู้ใช้ใหม่จริงสำหรับเกณฑ์เรียนรู้ภายใน 5 นาที
- ยังไม่มีหลักฐาน uptime ครบหนึ่งเดือน จึงไม่อ้างว่าผ่านเกณฑ์ 99% ต่อเดือน
- ผลโหลดและประสิทธิภาพที่บันทึกไว้เป็นผลในสภาพแวดล้อมทดสอบ ไม่ใช่การรับรองทุกเครื่องหรือโฮสต์

### 9. การติดตั้งแบบย่อ

- ติดตั้ง Node.js 24 ขึ้นไป และดาวน์โหลด/แตกโฟลเดอร์ Repository
- เปิด Terminal ในโฟลเดอร์โปรเจกต์ แล้วติดตั้งแพ็กเกจ
- เปิดระบบและเข้าหน้า http://127.0.0.1:3003
- ใช้บัญชีสาธิตที่ระบุใน README และข้อมูลตัวอย่างเท่านั้น

```sh
npm ci
npm start
```

npm start เปิดเซิร์ฟเวอร์โดยตรง หากต้องการ health monitor ตามคู่มือ ให้ใช้ npm run start:monitored หรือ Start-Tim-Rent-Car.cmd

- เจ้าหน้าที่: ทดลองจอง CAR-003 ในช่วงเวลาทับซ้อน ตาม TC2-U
